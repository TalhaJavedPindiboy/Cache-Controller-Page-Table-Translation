# Direct-Mapped Cache Controller with Page-Table Translation (No TLB)

## Project Overview
This project implements a hardware memory management and caching subsystem in Verilog HDL[cite: 33]. It combines a direct-mapped cache controller with a page-table-based address translation unit (MMU) that operates without a Translation Lookaside Buffer (TLB)[cite: 33]. 

In this design, every memory request generated by the processor must first undergo virtual-to-physical address translation through a synchronous page table RAM before any cache lookup can begin[cite: 33]. The architecture handles multi-process translation, page hit and page fault detection, direct-mapped cache lookup, line allocation and refill from main memory, and write-through data updates[cite: 33, 38, 48, 58].

---

## Architectural & Memory Specifications

* **Cache Architecture:** Direct-mapped organization containing 8 cache lines with a single tag comparator[cite: 34, 43].
* **Cache Line Size:** 128 bits (16 bytes), divided into four 32-bit words[cite: 34].
* **Page Organization:** 32 bytes per page (2 cache lines / 8 words per page)[cite: 34, 35].
* **Main Memory:** Backing memory of 32 lines (512 bytes total), organized into 16 physical page frames[cite: 34, 36].
* **CPU Data Interface:** 32-bit single-word data read and write operations[cite: 34].
* **Write Policy:** Write-through with write allocate[cite: 46, 58].

---

## Address Structure & Mapping

### Virtual Address (7 Effective Bits)
The processor generates a 32-bit virtual address, of which the lower 7 bits are used for address calculation[cite: 36]:
* **Virtual Page Number (VPN) `[6:5]`:** 2 bits selecting 1 of 4 virtual pages per process[cite: 36, 49].
* **Page Offset `[4:0]`:** 5 bits defining the byte position within the 32-byte page (1-bit line within page, 2-bit word offset, 2-bit byte offset)[cite: 35, 49].

### Page Table Translation & PTBR
The system accommodates two processes via Page Table Base Registers (PTBR)[cite: 38]:
* `processor_id = 0` maps to `PTBR0 = 0` (Page Table Entries 0 to 3)[cite: 38].
* `processor_id = 1` maps to `PTBR1 = 4` (Page Table Entries 4 to 7)[cite: 38].

The physical address translation unit accesses the synchronous page table RAM at address `selected_ptbr + vpn`[cite: 39, 49]. Each 5-bit Page Table Entry (PTE) consists of:
* **Bit 4 (Valid Bit):** A value of `1` indicates a Page Hit, whereas `0` triggers a Page Fault[cite: 37, 39, 57].
* **Bits [3:0] (Physical Frame Number - PFN):** The 4-bit frame address identifying 1 of 16 physical frames in memory[cite: 36, 37, 57].

### Physical Address (9 Effective Bits)
Upon a page hit, the translation logic concatenates the 4-bit PFN with the original 5-bit Page Offset to form a 9-bit effective physical address (`{PFN, Page Offset}`)[cite: 37, 40, 57]:
* **Tag `[8:7]`:** 2 bits compared against the stored tag register for the selected line[cite: 41, 42, 58].
* **Cache Index `[6:4]`:** 3 bits selecting 1 of the 8 cache lines[cite: 41, 42, 58].
* **Word Offset `[3:2]`:** 2 bits selecting the target 32-bit word from the 128-bit cache line[cite: 41, 58].
* **Byte Offset `[1:0]`:** 2 bits specifying byte alignment within the word[cite: 42].

## Controller Operation & Logic Flow

1. **Page Fault Suppression:** If an accessed entry is marked invalid (`Valid = 0`), the translation unit asserts `page_fault`[cite: 39]. The controller immediately blocks cache and main memory access, bypasses cache lookup, and halts the current request[cite: 40].
2. **Cache Lookup & Hit:** When a valid physical address is provided, the controller evaluates `valid_array[index] && (tag_array[index] == tag)`[cite: 58]. On a read hit, the selected 32-bit word is routed to `rdata` and `ready` is asserted[cite: 45, 58]. On a write hit, both the cache line and main memory are updated[cite: 46, 58].
3. **Cache Miss & Refill:** If the requested line is missing or invalid, the controller asserts `mem_read`, fetches the entire 128-bit line from main memory using physical address bits `[8:4]`, updates the cache data and tag array, sets the valid bit, and completes the operation[cite: 46, 58].

## Module Descriptions

* **`system_top.v`:** Top-level structural module that interconnects the processor control signals, translation unit, page table memory, cache controller, and backing memory[cite: 48, 61].
* **`address_translation.v`:** Combinational module that decodes the virtual address, calculates the PTE location based on `processor_id`, validates entry status, and forms the physical address[cite: 49, 57].
* **`page_table_ram.v`:** Synchronous RAM containing the 8 Page Table Entries supporting both processes[cite: 50, 60].
* **`cache_controller.v`:** Finite state machine managing status flags (`busy`, `ready`, `hit`), tag array matching, data multiplexing, miss refill coordination, and write-through transactions[cite: 47, 50, 58].
* **`main_memory.v`:** Synchronous 32-line $\times$ 128-bit memory backing the cache system[cite: 51, 59].
* **`system_tb.v`:** Testbench simulating sequential memory operations, process switching, page faults, cache misses, line refills, and conflict evictions[cite: 56].

## Verification Scenarios

The testbench (`system_tb.v`) verifies the design across multiple operation modes[cite: 56]:
* **Cold Cache Miss & Refill:** Fetching an unmapped block from main memory and allocating it into the cache[cite: 52, 56].
* **Multi-Line Page Access:** Accessing different cache lines within the same virtual page[cite: 56].
* **Multi-Process Isolation:** Switching between `processor_id = 0` and `processor_id = 1` to verify independent PTBR mapping[cite: 38, 56].
* **Page Fault Handling:** Requesting an invalid page table entry to confirm complete suppression of cache lookup[cite: 40, 56].
* **Cache Hit Verification:** Re-reading previously loaded lines to ensure single-cycle hit responses without main memory access[cite: 45, 56].
* **Conflict Miss & Eviction:** Accessing two distinct memory blocks mapping to the same cache index to confirm tag overwrite and data consistency[cite: 56].
